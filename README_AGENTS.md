# README_AGENTS · 给任意 AI Agent 的接管指引（工具无关版）

> 本战役（Campaign）以**纯文本文件 + git + Node 脚本**为唯一运行基础，**不绑定任何特定 agent 工具或模型**（opencode / Claude / DeepSeek / GPT / 本地模型均可运行）。任何能"读写文件 + 跑 git + 跑 node"的 agent 都可以接管本战役继续游玩。
>
> 阅读顺序：先读本文件 → 再读 `START_HERE.md`（全局手册）→ `AGENTS.md`（核心规则）→ `save-protocol.md`（存档协议）。

---

## 1. 战役是什么

这是一个长期、连续、开放式的**中世纪低魔奇幻文字游戏（RPG + GSG + SIM + SLG 四合一）**。文件系统就是世界与状态的权威（filesystem 为叙事权威，非对话记忆）。你（agent）担任 GM + 叙述者：运行世界、扮演 NPC、处理经济政治与后果、维持长期连续性。玩家只控制主角的言行、判断、感情与重大决定。

**战役形态（玩家定版）**：**领地开局变体**——主角为没落小贵族女继承人，开局继承一座贫瘠、负债、人口流失的领地并面临危机；主题为**领地发展与政治博弈**，保留角色扮演与感情线要素（凤傲天 / 长寿 / 女同生子 / 后宫保留）。工作流机制（五轮/间章/存档/计算/线级推进）完全不变。启动为**四阶段**：①世界（`WORLD_GEN.md`）→ ②政治地缘（`POLITICS_GEN.md`，一势力一条+势力台账）→ ③人物与势力（`CHARACTER_GEN.md` 领地版）→ ④正式游玩。`domain.md` 首日启用。

## 2. 恢复状态（每次接手的起点）

1. 读 `state.md`——**每轮必读**的当前快照（日期/位置/资源/在场班底/当前危机/当前主线线）。
2. 读 `chronicle.md`——纪事录，了解来龙去脉（叙事摘要，非全文）。
3. 按 `state.md` 的「当前主线线」读对应专题文件：领地→`domain.md`、政治→`politics.md`、商路→`commerce.md`、武装→`arms.md`、外出事务→`expedition.md`。
4. 读 `world.md`（世界设定，按需查）、`characters/`（角色档）、`ledger.md`（账本，含领主债务）、`clues.md`（调查线）、`quests.md`（领地事务板：危机清单/主线/种子）。涉政治线时读 `politics-ledgers.md`（势力台账，GM 私有，防漂移）。
5. `git log --oneline -10` 看存档脉络。

## 3. 五类轮（核心运营协议，不可混轮）

所有游戏流程**必为以下五类之一**，一轮对话内不得混入其它类的动作：

| 轮类 | 做什么 | 不做什么 |
|---|---|---|
| **① 生成轮** | 内部推演、生成底牌页、建立新线（阶段一至三也是生成轮） | 不叙事、不碰存档 |
| **② 推理轮** | 显式因果链拆解、后果推演、计算规划、逻辑硬伤自检（sequential-thinking，无则思维链书面化） | 不执行、不写文件、不存档 |
| **③ 操作执行轮** | 调脚本/工具算账、计算、写文件（除存档外） | 不推演、不叙事、不存档 |
| **④ 叙事轮** | 只写剧情/对话/场景 | 不碰文件/脚本/存档 |
| **⑤ 存档执行轮** | 存档四步（文件+memory+git+哈希） | 不叙事 |

每轮回复开头**明说轮类**。轮可跨多个对话来回（闭合段落），但一个来回内只推进一类轮的工作。

## 4. 存档四步（触发后执行，不可跳步）

触发点：战斗结束 / 新线索 / 过夜转场 / 重大决策 / 资产变动 / 政治局势重大变化 / 玩家喊"存档" / 场景段落告一段落。

1. 更新受影响文件（`state.md` 优先，`chronicle.md` 追加叙事摘要）；
2. 更新 memory（memory.json，JSONL；写操作串行）；
3. `git add` + `git commit`；
4. 贴出 `git log --oneline -3` 真实输出（**必须出示哈希，看不到哈希=没存成功**）。

工具不可用时降级：无 git → 用 CLI；无 memory 图谱 → 直接读写 memory.json；一律不阻塞游玩。

## 5. 轮次变体

- **先叙后算**：①叙事轮 → ②操作执行轮·结算 → ③存档执行轮。（如需结算推演，先加推理轮）
- **先算后叙**：①推理轮 → ②操作执行轮·计算 → ③叙事轮 → ④存档执行轮。
- **篇章间章**（大篇章后，防视野外世界停转）：①梳理轮 → ②推理轮 → ③操作执行轮 → ④补充叙事轮 → ⑤额外存档轮。领地开局下间章尤其重要：主角在领地或外出时，政治派系、邻家领主、领地收成/欠税、商路各自照常运转。

## 6. 铁律（不可违反）

1. 爽游——主角是凤傲天，强、赢、拿回报。领地之穷与危机来自局势与财政事实，不来自"削弱主角"——主角个人永远强。
2. 禁「平衡」「张力」「难度」三词与三思路。
3. 长寿对主角与班底是纯增益，无代价无倒计时。
4. 普通事务/委托就是普通事务/委托，不全是世界级阴谋。领地杂务（修桥、调解、护送、清剿）真实存在。
5. 经济先列假设后给结论；赚钱与领地产出只由世界事实决定。
6. 纯西式（无日式/中式元素）；取名西式；制度称谓西式。
7. 领地政治（税制/封臣义务/司法权/债务/联姻/教会）按真实中世纪封建机制运转，超凡只作点缀。
8. 涉及政治势力/成员前对照势力台账（`politics-ledgers.md` 的目的/性格/底线锚点），任何剧情不得违背其底线锚点——成员可摇摆/内斗/叛变但不得 OOC。

## 7. 工具无关的环境假设

- 本战役只依赖：**文件读写 + git CLI + Node.js**（跑 `scripts/`）。
- `scripts/` 内工具：`date.js`（历法）、`econ.js`（经济演算）、`save.js`（半自动存档+哈希）、`save-verify.js`（校验）、`ledger-check.js`（对账）、`blueprint-gen.js`（底牌页）、`npc-registry.js`（人物索引）、`season-event.js`（季节事件）、`skill-index.js`（skills 校验）。
- 若你的环境有 MCP（memory/filesystem/sequential-thinking/fetch 等）则用；没有就用上述降级映射（纯文本）。

## 8. 开始游玩

读完本文件与 `START_HERE.md`/`AGENTS.md` 后，给玩家 3–4 行"上回书"叙事开场（依 state.md 的时间/地点/当前事），再以场景化方式进入游玩，等玩家指令。
